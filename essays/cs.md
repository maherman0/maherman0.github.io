# My Experience

Cleaning up code is something that no one wants to do, but everyone needs to in order to have functional and clean code to run. This is what ESLint was designed to do. All of the syntax, styling, and runtime issues for JavaScript are debugged through this tool. As a first-time user myself, I thought coming into this that it was going to be similar to the compiler tool in Java, testing to see if the code runs. However, every time I tried to run my code, I’d find myself with even more errors than before. It is everything that your computer science teacher preaches to their students to do that the tool checks for. Finding each and every error and styling issue was a pain, as I was not used to the preciseness that ESLint requires.

After using it for a while, I think I’ve gotten used to the coding standards. Although the coding standards can be frustrating at times, I truly believe that it is the next step for programmers who’ve got the basics down. The sheer amount of time and effort it takes to replace your old habits in coding with good and clean coding practices will shape how developers see your code and you as a coder. It will also dictate how developers understand your code and how you understand it yourself when coming back to it later on.
