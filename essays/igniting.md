##Learning Type Script

Typescript like many other languages can be picked up if you have experience in coding other languages! Even though I had a limited amount of experience in Typescript or Javascript, I think that the syntax and ideas are pretty similar to Java, so learning the basic syntax wasn’t too hard as my experience in Java carried over and the puzzle pieces started to click. If you haven’t learned about typescript give it a shot as the language is useful for catching more potential errors and making sure your code doesn’t go whack with some simple fixes. 

##avascript vs Typescript

People may think Typescript and Javascript are the same thing. A lot of the syntax are very similar to each other, but if you look closely some things may not run in Typescript that would normally run in Javascript. Why? Well it's in the name Typescript, it takes into account the types of the things that are being compiled including the functions and variables. This is how Typescript separates compared to Javascript and even Java, but Typescript is unique in that it only allows good code to be run. Imagine if you had set age to 15, but you changed it to “fifteen”. In Javascript, this code would run just fine even though there is a type mismatch. Now try the same in Typescript and you will get an error. 

##Athletic Software Engineering

How can software engineering be athletic? Well when we think about an athlete, they are people who dedicate their time, money, and energy into a sport to produce better results. The same concept applies to software engineering and coding in general. No matter how much talent someone has for coding and figuring out how to solve problems, someone with 10 hours of experience in coding probably won’t be better than someone with 500 hours of coding. Now the gap usually isn’t a skill problem or talent, instead it is a lack of experience. Whether it is a lack of knowledge in syntax, finding solutions to an issue, or inability to fix bugs, coding can be improved upon putting in the reps to learn new syntax, finding more efficient solutions, and writing good code. WODs are a great example of this! WODs are timed problems that require the user to solve an issue in a certain amount of time. Now usually when one codes we don’t worry about the time or the extent of the code as long as it solves the problem we should be good. However when it comes to in real life settings, there won’t be the leisure time to relax, one must be able to work under the pressure to complete the problem. WODs are meant to simulate a real life situation with real work feelings to help the person adapt. I think adding them wasn’t meant for me, but I know in the long run it will be extremely helpful.
